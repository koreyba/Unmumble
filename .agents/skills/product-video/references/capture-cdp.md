# Отдельный маршрут: Chromium/CDP и звук вкладки

Читать только когда заказан звук продукта либо нужны отдельные кадры CDP. Основной немой захват и управление видимым iPhone описаны в [product-capture.md](product-capture.md). CDP работает только в Chromium; этот маршрут не является записью Safari/WebKit.

Используй [recorder.mjs](../scripts/recorder.mjs) через [capture-session.mjs](../scripts/capture-session.mjs). В конфиге явно задай `recording: "cdp"`, `browserType: "chromium"`, `audio: true` только для заказанного звука; модуль, URL, устройство и выходную папку проверь заново. Полный профиль сохраняет мобильную компоновку, но движок здесь Chromium.

Доверенный локальный сценарий экспортирует `async run({page, context, startRecording, output})`. Подготовь интерфейс и дождись готовности, затем:

```js
const take = await startRecording('trainer', { readState: async page => ({ url: page.url() }) });
await take.mark('before-action');
// Действие по текущему интерфейсу и проверка результата.
await take.mark('after-action');
await take.stop();
```

Выход дубля: JPEG в `frames/`, `frames.txt`, `capture.json`, снимки меток и, при заказанном звуке, `tab-audio.webm`. Все CDP-кадры ACK подтверждаются, но сохраняются лишь кадры, у которых `metadata.deviceWidth/deviceHeight` совпадают с измеренным viewport: первый кадр может иметь старый размер поверхности окна. Размер кадров отличается от DPR скриншота; координаты пересчитывай по фактическим файлам.

Для звука recorder запрашивает `getDisplayMedia` и сохраняет аудиодорожки через `MediaRecorder`. Требуются поддержка браузера, подходящий источник и аудиодорожка; launch-флаги не гарантируют захват. Сначала сними короткую пробу с воспроизведением, проверь и прослушай файл. Не переносить CDP/getDisplayMedia-рецепт в WebKit при ошибке.

В `capture.json` `frames[].time`, `marks[].time`, `end`, `audioStart` измерены в секундах от первого принятого кадра. Положительный `audioStart` означает более позднее начало аудио, отрицательный — более раннее. Вычисляй его заново; не смешивай эту шкалу с часами событий нативного WebM receipt.

Собирай `frames.txt` через FFmpeg concat с исходными временными интервалами, затем CFR по задаче. При собственном пересэмплировании выбирай последний кадр с временем не позже целевого. Подгоняй звук по той же шкале времени; для длинной записи проверяй дрейф. Не меняй темп речи носителя ради синхронизации.

При полной навигации audio recorder прежнего document теряется: заверши дубль до перехода и начни следующий после него. SPA-переход проверь пробой. После изменения recorder перезапускай Node-процесс, чтобы не пользоваться кешем старого модуля.
