# Product Video

Создавай цельную историю о продукте для выбранной площадки. Скилл задаёт процесс; тему, аудиторию, стиль и инструменты выбирай по задаче. При запросе отдельного этапа выполни только его.

## Бриф без анкеты

Используй сведения из разговора и проекта. Приоритет: текущие указания пользователя → бриф ролика → выбранный пресет → разумные предположения.

Если важные сведения отсутствуют, задай одним сообщением не более трёх вопросов:

1. Для кого ролик и насколько зритель знаком с продуктом?
2. Зачем ролик: заинтересовать, научить, объяснить изменение или другая цель?
3. Что зритель должен понять или сделать после просмотра?

Спрашивай только то, чего ещё не знаешь. Язык, длительность, настроение, материалы и площадки уточняй, когда ответ существенно влияет на результат. Иначе кратко обозначь предположения и продолжай. Не требуй согласования каждого этапа, если создание ролика уже поручено.

Сохрани рабочий бриф в папке ролика, используя [assets/brief-template.json](assets/brief-template.json). Заполни подходящие поля; пустые необязательные поля не блокируют работу. Формат, голос, музыка, титры и захват задаются явными полями. `enabled: false` выключает слой, `null` означает отсутствие переопределения; при отключении параметрического слоя явно отменяй наследование. При необходимости примеров прочитай [references/brief-settings.md](references/brief-settings.md). Настройки можно менять без переписывания скилла.

## Выбрать маршрут

- Для нового продукта выбери стиль по цели. Для продолжения Unmumble можно взять [assets/presets/unmumble-dynamic.json](assets/presets/unmumble-dynamic.json), если пользователь не задал другое.
- Проверь доступные MCP/CLI, инструменты и исходники перед Computer Use. Для местных инструментов прочитай [references/toolchain.md](references/toolchain.md).
- При демонстрации сайта прочитай [references/product-capture.md](references/product-capture.md): видимый Playwright, полный профиль устройства (iPhone → WebKit), управление через persistent Node REPL и встроенный `recordVideo`. Закрой записывающий контекст и проверь файл; звук вкладки имеет отдельный Chromium/CDP-маршрут.
- При выборе новой музыки прочитай [references/music-selection.md](references/music-selection.md): обязательные четыре отдельные пробы и выбор пользователя до добавления в видео.
- При экспорте или передаче на платформы прочитай [references/delivery.md](references/delivery.md).
- Читай специализированные скиллы только для нужного этапа: Remotion для композиции и анимации, FFmpeg для обработки медиа, YuE2 для запрошенной генерации музыки.

## История и сцены

### Рекламный сценарий: связка с маркетинговыми скиллами

Для нового рекламного ролика или изменения его смысла выполни следующие этапы до съёмки. При правке только монтажа или звука переиспользуй принятый сценарий.

1. **Контекст — [product-marketing](../product-marketing/SKILL.md).** Прочитай существующий `.agents/product-marketing.md` из репозитория продукта (поддерживаются прежние пути из стороннего скилла). Если контекста нет, используй скилл для его подготовки по известным сведениям; неизвестные боли и обещания обозначай как гипотезы. Обновляй контекст при изменении продукта или аудитории, а не для каждого ролика. Передай целевую аудиторию, одну боль, подтверждённую пользу, ограничения и нужный язык.
2. **Идея — [ad-creative](../ad-creative/SKILL.md).** Для одного ролика используй Generate from Scratch; прочитай его `references/hook-system.md` и подходящий формат из `references/short-form-video-specs.md`. Подготовь три разных коротких хука, выбери подходящий по брифу и построй цепочку: вопрос/зацепка → узнаваемая боль → решение → демонстрация результата → следующий шаг. Это предпочтение для рекламы, не обязательная структура другого жанра. Для каждого хука опиши кадр, первую реплику и титр. Сохраняй происхождение утверждений; не придумывай отзывы, цифры или функции.
3. **Редактура — [copy-editing](../copy-editing/SKILL.md).** Примени проверки ясности, пользы, доказательности и краткости к репликам и титрам. Одна мысль на реплику, простые разговорные слова, минимум текста при сохранении смысла. Убери повторы и перечни функций без пользы для зрителя. Сохрани выбранную боль, факты и действие; проверь длительность чтением вслух, после генерации голоса уточни её по аудио. Верни окончательную таблицу сцен, а не длинный отчёт о проверках.
4. **Производство — этот скилл.** Используй таблицу: `секунды | смысл | реплика (если голос включён) | титр (если включён) | что видно и происходит | наблюдаемый результат | исходники`. Включённые слои и стилистические настройки определяются брифом; для режима «скажи, затем покажи» сохраняй совпадение инструкции и речи. Переходи к производству в пределах поручения пользователя; запрос только сценария заканчивается таблицей.

Сторонние скиллы подключены без местных правок. Если ссылки отсутствуют, из корня этого репозитория выполни `git submodule update --init .agents/vendor/marketingskills`. Не заменяй отсутствующий скилл выдуманными инструкциями. Прямые указания пользователя и выбранный бриф имеют приоритет над настройками сторонних шаблонов; этот этап не разрешает запуск рекламных кампаний или публикацию.

Сформулируй одной фразой обещание ролика. Построй последовательность, где понятно, зачем нужно каждое действие. Возможная схема: зацепка → потребность → действие → наблюдаемый результат → следующий шаг. Для другого жанра выбери подходящую структуру.

До съёмки составь таблицу сцен: смысл, текст включённых титров/озвучки, что видно, действие и результат, нужные исходники, примерная длительность. Без голоса планируй длительность по читаемости текста и наблюдаемому действию. Не заявляй неподтверждённые функции, результаты обучения или бесплатность. Для утверждений пользователя сохрани происхождение; собственные утверждения проверь.

В стиле «скажи, затем покажи» сначала объясни действие крупным титром и, если включена озвучка, совпадающей репликой, затем покажи настоящую реакцию продукта. Например: «Missed it? Go back one phrase» объясняет причину возврата; отдельное «Back» её теряет. Не навязывай этот стиль всем жанрам.

В пресете Unmumble зацепка и финал остаются отдельными анимированными экранами, а инструкции к действию появляются рядом с демонстрацией в том же кадре. Титр и речь объясняют действие, курсор показывает кнопку, затем виден результат. Это сокращает лишние переключения; для других роликов компоновку выбирай по задаче.

Курсор, подсветка клика и приближение помогают найти кнопку. Координаты бери из снятого интерфейса. Анимируй масштаб в монтаже, сохраняя выбранную desktop/mobile компоновку. Порядок приближения, возврата и клика задаётся сценой. Если зум мешает увидеть результат, упрости его.

## Производство

1. Создай папку нового ролика или новую версию проекта. Сохрани оригиналы и утверждённый экспорт.
2. Если нужна новая съёмка, сними реальные действия в выбранной компоновке; проверь короткую пробу изображения и только заказанного звука продукта. Без звука не запрашивай его захват. Не выдавай мокап или монтажное повторение за работающий продукт.
3. Если озвучка включена, проверь поддержку языка, затем генерируй её отдельно по сценам выбранным голосом и скоростью. Рассчитывай длительность и синхронизируй титры по фактическому аудио. При изменении голоса обнови тайминги. Без озвучки пропусти TTS и обязательное чтение голосовых ресурсов.
4. Если выбирается новая музыка, всегда подготовь **четыре варианта: две новые генерации установленной локальной моделью и две дорожки с Pixabay Music по тому же описанию**. Предложи их отдельно для прослушивания и дождись выбора пользователя **до добавления музыки в видео**. Монтаж изображения, титров и озвучки продолжай независимо; до выбора отдавай версию без музыки. Сохрани источник/промпт и условия использования. При прямом указании сохранить выбранную/предоставленную дорожку переиспользуй её; при отключённой музыке пропусти подбор. Не выдавай неполный набор за четыре варианта.
5. Собери композицию из включённых слоёв. Согласуй склейки изображения и имеющегося звука, сохраняя смысл действий. Включённые титры должны читаться на целевом экране и учитывать перекрытия площадки; с озвучкой они совпадают с речью, без неё получают время на чтение.
6. При наличии музыки и речи приглуши музыку под голосом и речью продукта, подними её в паузах плавно. Без речи не создавай искусственное приглушение; без любых аудиослоёв экспортируй немой файл. Речь носителя по умолчанию сохраняй в естественном темпе.
7. Сохраняй аудиомастер в PCM/WAV; сжатие делай при экспорте с явными единицами битрейта. Если меняется только звук, переиспользуй готовое изображение без полного рендера. Выполни проверки доставки, сохрани финальное видео, редактируемые исходники и фактические ограничения.

При новой стилистике или техническом маршруте сначала собери одну характерную сцену только с предусмотренными брифом слоями. Для небольшого изменения проверенного ролика достаточно проверки изменённых частей перед полным экспортом.

## Эффективность и остановка

Переиспользуй пригодные исходники. Не открывай несколько браузеров и не повторяй полный рендер без нового основания. После неудачи установи причину и сделай адресную попытку исправления. Если причина остаётся неизвестной, инструмент отсутствует или результат по-прежнему непригоден, останови зависимый этап и сообщи: что проверено, что мешает, какой инструмент/материал нужен. Продолжай независимые полезные части.

В конце дай ссылку на результат и исходники, назови выполненную проверку и существенный незавершённый этап. Различай готовый ролик, сохранённый черновик и опубликованный пост. Публикуй или создавай черновики только в объёме прямого поручения пользователя.
