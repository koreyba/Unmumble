# Съёмка интерфейса через Playwright

Читать для новой съёмки сайта или управления браузером во время записи. URL, устройство и действия берутся из задачи. iPhone 16 и Unmumble ниже — рабочий пример, а не обязательный выбор для любого продукта.

## Основной маршрут

Используй **видимый Playwright + полный профиль устройства + встроенный `recordVideo`**. Для iPhone выбирай WebKit, для других устройств — `profile.defaultBrowserType`, если задача не требует конкретного движка. Это эмуляция браузера на компьютере, не настоящий iPhone/iOS.

Для показа пользователю и пошагового управления предпочитай доступный persistent Node REPL: браузер, контекст и страница остаются переменными между вызовами. Не требуется Computer Use, открытие DevTools или ручной выбор телефона. Перед выбором инструмента проверь доступные MCP/CLI. Для готового сценария без REPL используй [capture-session.mjs](../scripts/capture-session.mjs).

`recordVideo` записывает изображение страницы **без звука продукта**. Если заказан звук вкладки, прочитай отдельный [Chromium/CDP-маршрут](capture-cdp.md). Озвучка и музыка добавляются в монтаже независимо от звука вкладки.

## Проверить зависимости

Из действующего репозитория проверь установленный Playwright, профиль и executable:

```sh
node -e "const p=require('playwright'); console.log(require.resolve('playwright')); console.log(p.devices['iPhone 16']); console.log(p.webkit.executablePath());"
```

Проверь существование executable выбранного движка. Если WebKit отсутствует, установи его для этой версии Playwright из того же репозитория:

```sh
npx --no-install playwright install webkit
```

Если установка недоступна, сообщи конкретную ошибку; не подменяй движок молча. При недоступном Node проверь `load_workspace_dependencies`. Не устанавливай второй пакет Playwright, если подходящий уже есть. Создай отдельную папку результата вне исходников приложения; не перезаписывай предыдущую запись.

## Открыть видимый iPhone с записью

Код для persistent Node REPL; замени пути на действующие абсолютные. Используй `createRequire` от `package.json` проекта: именно этот способ сработал здесь. Прямой `import('.../playwright/index.mjs')` в этой REPL завершился ошибкой `does not provide an export named 'default'`; не повторяй тот же импорт после такого сбоя.

```js
var projectRoot = '/Users/denys.koreiba/Documents/Unmumble.online';
var output = '/absolute/new-video/capture';
var createRequire = (await import('node:module')).createRequire;
var requireProject = createRequire(projectRoot + '/package.json');
var pw = requireProject('playwright');
var fs = await import('node:fs/promises');
await fs.mkdir(output); // новая папка; её родитель уже существует

var profile = pw.devices['iPhone 16'];
if (!profile) throw new Error('Device profile is unavailable');
var browser = await pw[profile.defaultBrowserType].launch({ headless: false });
var context = await browser.newContext({
  ...profile,
  recordVideo: { dir: output, size: { ...profile.viewport } },
});
context.setDefaultTimeout(5000);
context.setDefaultNavigationTimeout(20000);
var page = await context.newPage();
var video = page.video();
await page.goto('https://unmumble.online/', { waitUntil: 'domcontentloaded' });
await page.bringToFront();
nodeRepl.write({ url: page.url(), title: await page.title() });
```

Запись начинается при создании страницы в этом контексте. К открытой странице без `recordVideo` запись задним числом не добавляется — нужен новый контекст. Окно остаётся открытым, пока живы REPL и браузер; не закрывай их в конце вызова запуска.

Полный профиль задаёт UA, viewport, screen, DPR, `isMobile` и `hasTouch`. Не добавляй второй независимый viewport и не переключай DevTools поверх профиля. `recordVideo.size` управляет размером файла, а не адаптивной компоновкой сайта. Явный размер предотвращает стандартное уменьшение записи до рамки 800×800. Кодировщик может округлить нечётные размеры: проверяй файл. Размер финального Reel 1080×1920 задаётся в монтаже, не в CSS viewport страницы.

Для desktop вместо профиля создай контекст с нужным `viewport`, например 1440×900, и таким же `recordVideo.size`; не применяй мобильный UA или `isMobile`.

## Проверить экран и управлять страницей

Следующий короткий вызов REPL:

```js
nodeRepl.write(await page.evaluate(() => ({
  width: innerWidth, height: innerHeight, dpr: devicePixelRatio,
  userAgent: navigator.userAgent,
  scrollWidth: document.documentElement.scrollWidth,
})));
await nodeRepl.emitImage(await page.screenshot({ scale: 'css' }));
```

Проверь мобильную компоновку, горизонтальное переполнение и видимость кнопки. Скриншот с DPR 3 по умолчанию больше CSS viewport: это не ошибка настройки телефона.

Находи элементы по **текущей роли и доступному имени**, а не по скопированному `textContent`. Для обзора:

```js
nodeRepl.write(await page.locator('a,button,[role="radio"],[role="tab"]').evaluateAll(es =>
  es.map(e => ({
    tag: e.tagName, role: e.getAttribute('role'),
    text: e.innerText.trim(), label: e.getAttribute('aria-label'),
    href: e.getAttribute('href'),
  }))
));
```

Каждое действие выполняй отдельным коротким вызовом. На текущем Unmumble:

```js
await page.getByRole('link', { name: 'Library', exact: true }).click({ timeout: 5000 });
await page.waitForURL('**/library', { timeout: 10000 });
await page.waitForTimeout(1500); // пауза для просмотра результата
nodeRepl.write({ url: page.url(), headings: await page.locator('h1,h2').allTextContents() });
```

Затем аналогично нажми ссылку `Practice` и проверь `**/practice`. Паузы помогают смотреть запись; готовность подтверждается URL, состоянием или видимым результатом. Для touch-сцены используй `locator.tap()` и проверь её отдельно; обычный `click()` подходит для показанных переходов.

Фильтр может иметь роль `radio`, даже если DOM-тег — `button`. Текст с динамическим счётчиком вроде `Common spoken forms22` не является надёжным доступным именем. После ошибки локатора перечитай роль/имя, а не увеличивай таймаут. Оставляй запас до лимита вызова REPL: здесь 30-секундное ожидание неверного локатора привело к сбросу ядра и потере переменных браузера. После сброса нельзя утверждать, что прежняя сессия по-прежнему управляется.

### Снять работающий плеер

Открой нужный пример, дождись готовности плеера и нажми его актуальную кнопку Play. Для текущего Unmumble кнопка имеет доступное имя `Play playback`, когда воспроизведение остановлено; не нажимай уже показывающую `Pause playback` кнопку ради «запуска». На другой странице заново прочитай её роль и имя.

Проверь фактическое воспроизведение минимум двумя наблюдениями: меняются кадры или субтитры и растёт позиция воспроизведения. Для HTML video можно наблюдать `paused`, `readyState`, `currentTime`; для внешнего iframe используй доступный API провайдера или наблюдаемое состояние продукта. Один успешный клик, загрузившийся iframe или buffering не подтверждают воспроизведение. Не подменяй недоступный внешний плеер мокапом и не обходи ограничения ради записи.

В Unmumble Replay может перейти в buffering; возврат требует загруженной истории. Для Repeat сними два фактических цикла — копирование фрагмента в монтаже не подтверждает функцию. Сохраняй кадр до действия и наблюдаемый результат после него. Для заказанного звука используй отдельный проверенный аудиомаршрут; немой `recordVideo` не содержит речь из плеера.

## Завершить и проверить видео

Закрой **записывающий контекст** и дождись `saveAs`:

```js
var lastUrl = page.url();
await context.close();
await video.saveAs(output + '/raw.webm');
nodeRepl.write({ file: output + '/raw.webm', bytes: (await fs.stat(output + '/raw.webm')).size });
```

Не жди немедленного завершения `video.saveAs()` до закрытия страницы/контекста: оно ждёт окончания записи. Открытое окно и `page.video()` ещё не доказывают готовый файл.

Если пользователь хочет оставить браузер открытым, создай в том же `browser` новый контекст с тем же профилем без записи, открой `lastUrl` и вызови `bringToFront()`. Если продолжает снимать — создай следующий записывающий контекст с новой папкой. Когда работа закончена, вызови `await browser.close()`.

Проверь установленным `ffprobe` ненулевую длительность, видео-дорожку и реальные размеры. Извлеки кадры до/после действий и посмотри их. `raw.webm` — исходник без звука; при передаче или монтаже конвертируй через FFmpeg по [delivery.md](delivery.md). Не подменяй проверку изображения проверкой наличия файла.

## Качество исходника и видимый курсор

Для просмотра действий проверенный нативный WebM достаточен. Для мастер-ролика 1080×1920 стремись к **реальному изображению интерфейса шириной не меньше 1080 пикселей**, с запасом для приближения, сохраняя mobile CSS viewport. Исходник может иметь другое соотношение сторон; кадрирование и размещение в 9:16 делаются на монтаже. Не увеличивай CSS viewport до ширины экспорта и не называй обычный upscale улучшением детализации.

В отдельной пробе WebKit с тем же CSS 393×659 и `recordVideo.size: {width:1179,height:1977}` сохранил 1178×1976, но кадр содержит прежнее маленькое изображение в левом верхнем углу и серое поле. Значит увеличение одного `recordVideo.size` **не является рабочим способом получить высокое разрешение интерфейса**. `deviceScaleFactor: 3` тоже не гарантирует DPR 3 в нативном видео.

В той же пробе `page.screenshot({scale:'device'})` дал чёткое изображение **1179×1977** при неизменной мобильной вёрстке. Последовательность таких кадров можно собирать через FFmpeg, сохраняя реальные временные интервалы, но прежде нужна отдельная проба скорости и плавности захвата. Записанный 25 fps WebM подтверждён; плавная съёмка DPR 3 на 30/60 fps пока не подтверждена. Дополнительный Chromium/CDP-маршрут тоже проверяй по реальным кадрам, не по размеру контейнера. Для обычных UI-роликов разумный монтажный ориентир — 30 fps; преобразование 25→30 не создаёт новых фаз движения.

Системный курсор в эту нативную запись не попал. Для Unmumble добавляй курсор, подсветку клика и зум в Remotion по сохранённым координатам и проверенным таймкодам. Бери координаты фактической кнопки из `boundingBox()` после прокрутки и пересчитывай их из CSS-размера в размер исходного кадра. Для mobile можно выбрать кружок касания; вид определяется задачей. Если пользователь хочет курсор уже в браузере, альтернативой служит DOM-маркер с `pointer-events: none`, следующий за `page.mouse.move(..., {steps})`; после навигации его нужно устанавливать снова. Курсор не должен перекрывать результат действия. Эти варианты ещё не проверены текущей пробой и не должны объявляться уже записанными.

## Повторяемая съёмка из CLI

Скопируй [capture-config.json](../assets/capture-config.json) в папку ролика. Заполни `playwrightModule` абсолютным путём к установленному `playwright/index.js`, `url` и `output` новой, ещё не существующей папкой. Пути разрешаются относительно JSON-конфига.

```sh
node .agents/skills/product-video/scripts/capture-session.mjs /absolute/new-video/capture-config.json
```

Для глобального запуска используй фактический путь к helper внутри установленного скилла. По умолчанию helper использует нативное видео, выбирает движок из профиля, снимает короткую пробу и завершает браузер. Это конечный CLI-процесс; для свободного управления в нескольких вызовах используй REPL выше.

Для прежних CDP-сценариев с `startRecording` явно добавь в старый конфиг `recording: "cdp"` и `browserType: "chromium"`. Новый основной режим использует `mark` и пишет один WebM на страницу; прежние manifests кадров и аудио остаются отдельным форматом.

Результат: `raw.webm`, `probe.png`, `session.json`, `capture.json`, снимки меток. Без `scenario` записывается только проба. Для действий укажи доверенный локальный `.mjs`, экспортирующий:

```js
export async function run({ page, context, mark, output }) {
  await mark('before-library');
  await page.getByRole('link', { name: 'Library', exact: true }).click();
  await page.waitForURL('**/library');
  await mark('after-library', { url: page.url() });
  await page.waitForTimeout(1500);
}
```

`mark` сохраняет снимок, наблюдаемое состояние и время по часам процесса. Это не точный таймкод WebM: привязку сцен проверь по видео. При ошибке helper сохраняет доступное видео и receipt со статусом `failed`, затем завершается с ошибкой. Такой файл не объявляй успешным дублем.

## Подтверждённая проба и ограничения

1 октября 2026: Playwright 1.62.1, видимый WebKit, `devices['iPhone 16']`, CSS 393×659, DPR 3. После реальных кликов Library → Practice записывающий контекст закрыт и сохранён WebM: VP8, **392×658, 25 fps, 5,8 секунды, 366144 байта**, без аудиодорожки. `ffprobe` и просмотр извлечённых кадров подтвердили обе страницы в видео. Это доказывает запись изображения и навигацию; не подтверждает звук, touch-жесты, авторизацию или функции плеера. Импорт через `createRequire` проверен отдельно в persistent REPL.

Передай в монтаж видео, снимки и manifest с URL, устройством/движком, размерами, действиями, результатами и ограничениями. Для локального приложения добавь текущий commit и dirty-состояние; для удалённого сайта локальный SHA не является подтверждённой версией deployment.

Официальная справка: [эмуляция](https://playwright.dev/docs/emulation), [видео](https://playwright.dev/docs/videos), [Video.saveAs](https://playwright.dev/docs/api/class-video#video-save-as).
